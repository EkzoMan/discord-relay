# Discord Relay

Бот-ретранслятор для Discord: читает сообщения из выбранных **исходных каналов**
одного сервера и пересылает их через **webhook** в другой Discord-сервер.
Управление каналами-маппингами выполняется через простой web-интерфейс
(FastAPI + Jinja2) — без перезапуска бота.

Каждый маппинг — это правило «канал → webhook»: сообщение, опубликованное в
исходном канале, появляется в целевом канале от имени исходного автора
(имя и аватар сохраняются), а вложения передаются ссылками в блоке
`Вложения:`.

## Основные возможности

- **Web-интерфейс**: добавление, удаление и тестирование маппингов; изменения
  вступают в силу сразу (бот читает хранилище при каждом входящем сообщении).
- **Сохранение автора**: пересылаются имя (display name) и аватар автора
  сообщения; длина урезается под лимиты Discord (username ≤ 80, контент ≤ 2000 символов).
- **Вложения**: ссылки на вложения добавляются к тексту под заголовком `Вложения:`.
- **Без нежелательных пингов**: пересылаемый контент отправляется с
  `allowed_mentions: {"parse": []}` — упоминания `@role`/`@everyone` не срабатывают.
- **Защита от петель**: сообщения, созданные webhook'ами (в том числе вашим же
  ботом-ретранслятором), всегда игнорируются; сообщения от ботов игнорируются
  по умолчанию (см. `RELAY_ALLOW_BOT_MESSAGES`).
- **Безопасное хранение секретов**: webhook URL отображается в UI замаскированным,
  в логи не попадает; принимаются только настоящие URL Discord-webhook
  (`https://discord.com/api/webhooks/...` или `https://discordapp.com/api/webhooks/...`).
- **Валидация**: идентификатор канала — только положительное число (snowflake);
  дубликаты маппингов на один канал запрещены.
- **Персистентность**: конфигурация хранится в JSON-файле (`RELAY_CONFIG_PATH`),
  запись атомарная (временный файл + `os.replace`) — конфиг переживает
  перезапуск контейнера.
- **Опциональный HTTP Basic Auth** для всех маршрутов UI/API
  (`UI_USERNAME` + `UI_PASSWORD`).
- **Работает в двух режимах**: UI-only без токена (для отладки) или полный
  relay с токеном бота.

## Требования

- **Python 3.12** (зависимости зафиксированы под эту версию в `requirements.txt`:
  `discord.py`, `fastapi`, `uvicorn[standard]`, `httpx`, `jinja2`,
  `python-multipart`, `pydantic`; для тестов — `pytest`, `pytest-asyncio`).
- Либо **Docker + Docker Compose** (образ `python:3.12-slim`, контейнер работает
  под непривилегированным пользователем `relay`).
- Аккаунт Discord с правами на создание приложения
  ([developer portal](https://discord.com/developers/applications)) и
  права администратора сервера для создания webhook.
- В исходящем направлении нужен только HTTPS-доступ к `discord.com`
  (webhook API); БД и внешние сервисы не требуются.

## Настройка Discord-приложения (пошагово)

1. Откройте <https://discord.com/developers/applications> →
   **New Application**, задайте имя.
2. Вкладка **Bot** → **Reset Token** → скопируйте токен
   (показывается один раз) — это значение `DISCORD_BOT_TOKEN`
   (см. также раздел «Получение DISCORD_BOT_TOKEN» ниже).
3. **Обязательно**: на той же вкладке **Bot**, блок *Privileged Gateway Intents*,
   включите **MESSAGE CONTENT INTENT** и сохраните. Без этой настройки бот
   будет видеть пустой текст сообщений — пересылка содержимого невозможна.
4. Вкладка **OAuth2 → URL Generator**:
   - Scopes: `bot`;
   - Bot Permissions: **View Channels** (бот не пишет сообщения в исходный
     сервер — он только читает каналы и отправляет в webhook, поэтому право
     *Send Messages* на исходном сервере не требуется).
5. Скопируйте сгенерированную ссылку, откройте её в браузере и добавьте бота
   на сервер с **исходными** каналами. Убедитесь, что бот имеет доступ к нужным
   каналам (для приватных каналов — соответствующие права).

### Получение DISCORD_BOT_TOKEN

Токен берётся из developer portal: приложение → **Bot → Reset Token**.
Reset генерирует новый токен и **аннулирует старый**. Если токен скомпрометирован —
сразу сделайте Reset. Токен — секрет: передавайте его только через переменные
окружения, не коммитьте в git и не вставляйте в переписку.

### Получение webhook URL (целевой канал)

На сервере, **куда** нужно пересылать сообщения:

1. Настройки сервера → **Integrations → Webhooks** → **New Webhook**.
2. Выберите целевой канал, при желании настройте имя/аватар webhook'а.
3. **Copy Webhook URL** — скопируйте ссылку вида
   `https://discord.com/api/webhooks/<id_канала>/<секретный_токен>`.

Последний сегмент URL — секретный токен: тот, кто знает полный URL, может
писать в канал. Храните его как пароль (UI показывает только первые 8 символов токена).

### Как узнать ID исходного канала

В Discord: Настройки пользователя → **Advanced** → включите **Developer Mode**.
После этого: правый клик по каналу → **Copy Channel ID**.

## Переменные окружения

| Переменная | По умолчанию | Описание |
| --- | --- | --- |
| `DISCORD_BOT_TOKEN` | *(пусто)* | Токен бота. Обязателен для пересылки; без него работает только web-UI (в логах — предупреждение, статус «Bot disabled»). |
| `RELAY_CONFIG_PATH` | `/data/config.json` | Путь к JSON-файлу с маппингами. В Docker `/data` — volume. **При локальном запуске на Windows обязательно задайте локальный путь**, например `./data/config.json`. |
| `PORT` | `8000` | Порт uvicorn. В `docker-compose.yml` проброс зафиксирован как `8000:8000` — при изменении `PORT` синхронно поменяйте маппинг портов. |
| `UI_USERNAME` | *(пусто)* | Логин HTTP Basic Auth. |
| `UI_PASSWORD` | *(пусто)* | Пароль HTTP Basic Auth. Авторизация включается **только если заданы обе** переменные; тогда она защищает все маршруты UI и API. |
| `RELAY_ALLOW_BOT_MESSAGES` | `false` | `true` — пересылать также сообщения авторов-ботов. Сообщения от webhook'ов игнорируются всегда (защита от петель). |
| `RELAY_LOG_LEVEL` | `INFO` | Уровень логирования: `DEBUG`, `INFO`, `WARNING`, `ERROR`. |

Значения `RELAY_ALLOW_BOT_MESSAGES`, принимаемые как «истина»: `1`, `true`,
`yes`, `on` (без учёта регистра). Пустая строка трактуется как «не задано».

## Запуск локально через Python

```powershell
# из корня проекта (PowerShell)
py -3.12 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt

# настройки передаются через переменные окружения:
$env:DISCORD_BOT_TOKEN   = "<токен бота>"          # можно не задавать для UI-only
$env:RELAY_CONFIG_PATH   = "./data/config.json"    # на Windows смените default /data/...
$env:PORT                = "8000"                  # необязательно
$env:UI_USERNAME         = "admin"                 # необязательно
$env:UI_PASSWORD         = "<стойкий пароль>"      # необязательно
$env:RELAY_ALLOW_BOT_MESSAGES = "false"
$env:RELAY_LOG_LEVEL     = "INFO"

python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
# альтернатива: python -m app.main  (порт берётся из $env:PORT)
```

Откройте <http://localhost:8000>.

> **Важно:** приложение **не читает файл `.env`** — `.env` предназначен только
> для `docker compose` (`env_file`). При локальном запуске экспортируйте
> переменные в оболочку, как показано выше (в Linux/macOS: `export VAR=...`).

## Запуск через Docker / docker compose

```bash
# 1. Создайте .env на основе примера и заполните значения
copy .env.example .env        # Windows
# cp .env.example .env        # Linux/macOS
notepad .env                  # заполните DISCORD_BOT_TOKEN и опции

# 2. Соберите и запустите
docker compose up -d --build

# 3. Смотрите логи подключения и пересылки
docker compose logs -f

# Остановка (конфигурация останется в volume relay-config)
docker compose down
```

Нюансы compose-варианта:

- Без файла `.env` `docker compose` не запустится (он указан в `env_file`).
- Маппинги хранятся в именованном volume `relay-config` внутри контейнера по
  пути `/data/config.json` — переживают `docker compose down` и пересборку образа.
- Контейнер работает под непривилегированным пользователем (uid 10001).
- Порт хоста зафиксирован: `http://localhost:8000`.

## Web-интерфейс

Дашборд на `/` состоит из трёх блоков:

1. **Relay status** — состояние бота: `Connected` (gateway активен),
   `Connecting / disconnected` (задача запущена, ещё не подключилась) или
   `Bot disabled` (токен не задан). Рядом — число маппингов и путь к конфиг-файлу.
2. **Mappings** — таблица: имя, ID исходного канала, **маскированный** webhook URL.
   Для каждой строки:
   - **Test** — отправляет в целевой канал тестовое сообщение через этот webhook
     (без аватара, заголовок `Relay test — <имя>`);
   - **Delete** — удаляет маппинг (с подтверждением в браузере).
3. **Add a mapping** — форма добавления: `Label (optional)` (до 64 символов),
   `Source channel ID`, `Target webhook URL`. Валидация и дубликаты отклоняются
   с сообщением на странице; успех/ошибка показываются flash-уведомлением.

Все действия (добавление/удаление) сохраняются в JSON сразу и применяются
мгновенно — перезапуск не нужен. При заданных `UI_USERNAME`/`UI_PASSWORD`
каждый маршрут, включая `/health` и `/status`, запрашивает Basic Auth.

Дополнительные JSON-эндпоинты: `GET /status` (bot_enabled / bot_running /
число маппингов / путь конфига) и `GET /health` (`{"status": "ok"}`).

## Как проверить, что всё работает

1. **Тесты** (не требуют сети и токена):

   ```powershell
   python -m pytest -q
   ```

2. **Запустите приложение** (локально или `docker compose up -d`) и откройте
   <http://localhost:8000> — статус должен стать `Connected`
   (в логах: `Relay bot connected as <bot> (id=...)`).
   Проверить JSON-эндпоинты: `curl http://localhost:8000/health`.
3. **Тест маппинга**: в таблице нажмите **Test** — в целевом канале появится
   сообщение «🔔 Test message from Discord Relay…», а на дашборде — зелёное
   уведомление «Test message sent».
4. **Сквозная проверка**: напишите сообщение в исходный канал — оно должно
   появиться в целевом от имени автора с его аватаром; вложения — блоком
   `Вложения:` со ссылками. В логах — строка `Relayed message <id> from
   channel <id> via mapping <id>`.
5. **Типичные причины, почему не работает**:
   - не включён **Message Content Intent** → бот не видит текст сообщений,
     пересылка содержимого невозможна;
   - бот не добавлен на сервер исходного канала или не видит канал;
   - неверный/отозванный токен → `Discord rejected DISCORD_BOT_TOKEN` в логах;
   - webhook удалён или изменён → `Webhook rejected the message with HTTP 404`
     (или иной статус).

## Безопасность

- **Не храните токены и webhook-URL в репозитории.** Секреты передаются только
  через переменные окружения. Файлы `.env`, `data/` и `config.json` уже
  исключены в `.gitignore`; в репозитории лежит только `.env.example` без значений.
- **Basic Auth включается опционально**: при заданных `UI_USERNAME` и
  `UI_PASSWORD` все маршруты UI и API защищены (сравнение через
  `secrets.compare_digest`). Без них доступ к порту должен быть ограничен
  локально/VPN — интерфейс умеет добавлять произвольные правила пересылки.
- **Маскирование webhook URL**: в дашборде показывается только префикс токена
  (8 символов), полный URL нигде в UI не отображается и **не попадает в логи**
  (логируются лишь классы ошибок HTTP и статусы ответов).
- **Валидация webhook URL**: принимаются только адреса настоящих Discord
  webhooks — нельзя указать произвольный URL («утечка» данных на сторонний сервер
  через UI отклоняется).
- **Отсутствие ping'ов**: пересылаемый контент не может упомянуть `@everyone`/роли.
- **Защита от циклов**: webhook-сообщения игнорируются всегда; бот-сообщения —
  по умолчанию.
- **Контейнер** работает от непривилегированного пользователя; конфиг пишется
  атомарно (не «полусостоявшийся» файл при сбое).
- Basic Auth не шифрует трафик: выставляйте интерфейс наружу только через
  reverse-proxy с TLS, а не напрямую.

## Ограничения MVP

- **Нет очереди повторных попыток при HTTP 429 и других ошибках**: если
  Discord отклонил пост (rate limit, удалённый webhook, сети нет), сообщение
  **теряется** — фиксируется только предупреждение в логе.
- **Нет CSRF-защиты**: формы UI не содержат CSRF-токенов — при включённом
  публичном доступе это дополнительная причина держать Basic Auth включённым.
- **Пересылается только текст + ссылки на вложения**: embed'ы, стикеры,
  контекст ответов (reply), редактирования и удаления сообщений **не**
  обрабатываются; редактирование в исходном канале не обновляет пересланное
  сообщение.
- **Длинные сообщения обрезаются** до 2000 символов (не разбиваются на несколько).
- **Один маппинг на канал**: несколько webhook'ов на один исходный канал
  настроить нельзя (дубликаты отклоняются).
- **Нет встроенного TLS** — сервер отдаёт только HTTP; при выносе наружу
  шифрование обеспечивает reverse-proxy.
- Ручное редактирование `config.json` «на живую» не поддерживается: приложение
  использует in-memory-состояние и перезапишет файл при ближайшем изменении
  через UI.

## Структура проекта

```
app/
  main.py        — FastAPI: маршруты UI/API, Basic Auth, lifespan с фоновой задачей бота
  relay_bot.py   — discord.Client: слушает on_message, фильтрует, вызывает webhook
  webhooks.py    — POST в Discord webhook (httpx), маскирование ошибок
  store.py       — потокобезопасное JSON-хранилище маппингов (атомарная запись)
  models.py      — Pydantic-модели и валидация webhook URL / канала
  settings.py    — чтение конфигурации из переменных окружения
  templates/     — base.html, index.html (Jinja2)
tests/           — pytest-тесты (routes, store, webhooks; без сети и токена)
Dockerfile       — python:3.12-slim, non-root, CMD uvicorn с ${PORT}
docker-compose.yml — сервис + volume relay-config + env_file .env
.env.example     — шаблон переменных окружения
requirements.txt — зафиксированные зависимости (Python 3.12)
```

Формат конфига: `{"mappings": [{"id": "...", "name": "...", "source_channel_id": 123, "target_webhook_url": "https://discord.com/api/webhooks/..."}]}`.
